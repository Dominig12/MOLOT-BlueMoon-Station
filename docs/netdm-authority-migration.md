# Сеть как единственный транспорт: миграция (17.11.2026)

Правило проекта: если устройство обменивается данными или отдаёт команду другому устройству, результат возникает только после прохождения запроса и ответа через netDM. Отсутствие маршрута, Host, питания, подходящего сервиса или квитанции **не является** условием для legacy-fallback. Локальная механика машины (проверка её питания и доступа, физическое открытие двери после доставки) выполняется в DM.

## Текущая стадия

- Дверные контроллеры: режим исполнения только через сетевые команды. Неуспешное планирование/отсутствующий контроллер больше не исполняет массовую legacy-команду.
- PDA: режим только через message-server. Неподдержанные форматы (широковещательные, фото, автоматизированные) пока явно отклоняются, а не обходят сеть. Нужны отдельные контракты и тесты для полного игрового покрытия.
- Радио: subspace uplink без fallback к мгновенному вызову локальных receivers. Аналоговый и последующий этап физического вещания — отдельная механика, ещё требует аудита.
- Research: использование ledger запрашивается всегда; до завершения синхронизации и без сервера консоль не выполняет legacy-покупку. Привязка сервера не угадывается по географической дистанции. Дисковые операции без сетевого сервера отклоняются.
- Атмосферные сенсоры, отдельные legacy-операции R&D, процессы устройства вне поддержанных категорий, radio backup, команды атмос-насосов и терминалов требуют дальнейшего переноса. **Проект ещё не полностью авторитативен**.

## Контрольные инварианты

1. Нет прямой доставки `sender -> recipient` в DM по REF или через глобальный список для сетевого действия.
2. Ответ «принято в очередь» не эквивалентен исполнению; результат признаётся после доставки и применения.
3. Восстановление соединения не исполняет действие повторно без ключа идемпотентности.
4. Недоступный Host даёт отказ/ожидание, а не legacy-транспорт.
5. Исключения форматов/каналов отображаются игроку и покрываются тестами.
6. Каждое физическое изменение исполняется на объекте-получателе при обработке доставленной команды.

Старые Shadow классы пока содержат телеметрию миграции и тесты. Это технический долг: удалить сравнения и переименовать реализации после замены тестов, сохранив диагностику отказов и журнал событий.

## Режим запуска и тесты (17.11.2026)

Начиная с этого изменения игровой netDM включается при `NETDM_IPC_MODE=v1` и не зависит от `NETDM_OBSERVE=1`. Старые тесты сравнения с параллельным legacy-транспортом удалены. Остаются сетевые авторитативные тесты R&D, PDA, radio uplink, дверей и нового сетевого отображения атмосферных показаний. Если bridge/Host отсутствует, сетевые операции должны быть явно недоступны, а не возвращаться к старым глобальным вызовам.


## Редактор Network Shell и переход устройств на события (17.11.2026)

Терминал предоставляет начальный IDE для сценариев: номера строк, структуру `observe/on/every/if/wait`, подсказки из локального каталога команд и ранее обнаруженных сетевых сервисов, заполнение по Tab и проверку исходника. Кнопка **«Проверить код»** вызывает отдельную команду `network.shell/check` по существующему сетевому маршруту. Host проверяет тот же синтаксис, что при запуске программы, но **не выполняет ни одной фазы, не создаёт program ID и не отправляет сетевых команд**. Ответ `valid` означает успешную статическую проверку, но не гарантирует доступность сервисов и их физическую достижимость при выполнении.

Атмосферные сенсоры и консоли уже обмениваются `atmos.sample` через сетевые публикации и подписки; переводить их повторно не нужно. Следующий пилот — **атмосферная тревога**: wall alarm публикует `atmos.alarm_state` при событии `post_alert` и предоставляет ту же полезную нагрузку в `read` для одноразового снимка. Подписчики получают обновления только через `ServiceRuntime.Publish` с реальной доставкой и ACK. Состояние измеряется на машине, а не подменяется кешем у клиента. Если Host отсутствует, события не создаются локально «задним числом».

Пример программы после обнаружения конкретного instance через `services -type atmos.alarm`:

```text
observe atmos.alarm.e42 -key emergency -mode queue -pending 4
on events -key emergency | where alarm -eq true
$event | select instance pressureKPa danger alarm
```

Здесь `atmos.alarm.e42` — **условное** имя; в игре нужно использовать ID существующей панели. `read reason=inspect` остаётся необходимым для первоначального снимка, если требуется состояние сразу после подписки. Событийная подписка сообщает только о будущих переходах, не воспроизводит пропущенное.

Технический долг: вещание локальной атмосферной тревоги через старые оповещения станции пока существует отдельно; остальные потребители этого канала нужно мигрировать по одному, не заменяя их мгновенным прямым вызовом.

# NetRun first release: accepted scope

The user approved the ordered roadmap in this conversation with «Действуй по порядку» and subsequently requested continuation. This document records that existing approval; it does not introduce a new approval gate.

1. Correct map input at TGUI CSS zoom/DPI, including hit, hover, pan, wheel and inertia.
2. Give every delivery an owned operation context, complete node metadata journals and bounded UI history with actual outcomes.
3. Execute ready deliveries through the existing budgeted scheduler and support bounded DNS failover without repeating commands.
4. Add quick selected-node actions, double-click management, access/activity/threat views and a structured packet journal with actual-route highlighting.
5. Publish argument schemas from the CLI registry; use them for completion, validation, help and a command palette.
6. Place existing archives safely and add small useful network work orders using real files/photos and unforgeable provenance.
7. Give ICE remembered observations/search/decoys, and legitimate administrators defensive actions: key rotation, temporary endpoint quarantine and resource-limited patrol restoration.

## Constraints and decisions

- Extend the existing DM OOP contracts and React/TGUI/PixiJS implementation; do not add a second renderer or framework.
- Server authorization, native machine checks, physical routing and cancellation remain authoritative at delivery.
- Preserve the user's current `net-feature` checkout and existing commits; no reset, automatic merge, push or publication.
- Payload bodies, private messages and object references must not enter operation/packet metadata.
- UI receipt and actual delivery outcome are separate. Native handling does not promise a later physical effect.
- Delivery scheduling must remain fair, bounded and nonblocking when a native callback yields.
- DNS retries share a deadline and generation guard; data commands are sent only after discovery, never replayed after execution.
- Map activity represents sampled recent events, not measured bandwidth or packets per second.
- Stashes require native power and explicit isolated direct-port binding. Never overwrite occupied station tiles or invent graph edges.
- Keep scope small: no new currency, persistent economy, arbitrary scripting or antagonist role.
- Tests are authorized by the user's later request to test the full mechanic, superseding the earlier temporary request not to write tests.
- Run only one DM compiler/world in this checkout at a time.

## Alternatives considered

The accepted approach extends existing contracts. A second transport scheduler, a full frontend rewrite, and a new progression economy would duplicate working infrastructure and expand release risk. The current proposal instead shares metadata and scheduling while retaining each delivery's authorization policy.

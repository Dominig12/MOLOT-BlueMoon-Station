# netDM — игровой интерфейс и глубина взаимодействия

Статус: **основной продуктовый план**. Принят 17 ноября 2026 года.
Рабочие ветки: `MOLOT-BlueMoon-Station/net-feature-dmcore-new` и `netDM-core/feature/byond-native-bridge`.

## Направление

Сеть — существующая физически-логическая игровая система, но интерфейс **не должен заставлять игрока быть сетевым инженером**.
Обычному сотруднику достаточно обнаружить устройство, прочитать состояние и получить понятное подтверждение результата.
Инженер или нетраннер может добровольно раскрывать маршруты, сервисные API, подписки, диагностику и скрипты.

**Прогрессивное раскрытие сложности** — не упрощённая «фальшивая» сеть: простые кнопки вызывают ровно те же
операции `ServiceRuntime` и получают те же сетевые результаты, что и Shell. При отсутствии питания, маршрута,
Host, прав или доставки нет локального shortcut/fallback. Нельзя путать «отправлено» и «применено».

## Три уровня глубины

| Уровень | Для кого | Что видит |
| --- | --- | --- |
| 1. Обзор (по умолчанию) | Любой игрок | Понятный статус подключения, несколько безопасных действий, список ближайших доступных сервисов, человеческое объяснение ожидания/отказа |
| 2. Исследование | Любопытный техник | Список устройств и категорий, их наблюдение, показания, история событий, сведения о доставке |
| 3. Инструменты | Инженер / нетраннер | Терминал, API и маршруты, IDE, скрипты, программные подписки, отладочные сведения |

Углубление выполняется **по желанию**; переход обратно в обзор никогда не удаляет результаты, программы, подписки или черновик.

## UI и визуальный язык

- Компактная «панель управления», не стартовый экран из дюжины технических кнопок.
- Понятные глаголы: «Найти устройства», «Тревоги», «Карта сети», «События», «Подробнее».
- Чёткая иерархия: главное действие → последнее наблюдение → менее важные настройки.
- Спокойная тёмная палитра станции, выразительная типографика, деликатные границы и небольшие цветовые акценты.
- Статус только по реальным данным endpoint/Host; «отправлено» и «успешно применено» визуально различимы.
- Ошибки показывают действие («нет связи — проверьте маршрут»), а не только wire status.
- Не загружать все данные при открытии: discovery и запросы — по явному действию игрока.
- UI не выдаёт полный API, raw JSON или скрипт, пока игрок сам не открывает инструменты.

## Текущий цикл (приоритет)

1. Переработать Network Terminal по принципу обзор → исследование → инструменты.
2. Привести поиск и карточки сервисов к простым понятным действиям без обязательных команд Shell.
3. Показывать последнее сетевое действие и его **реальное** состояние; ожидание результата не изображать успехом.
4. Оставить доступ к существующему терминалу, IDE, справке, TGUI-диску и истории без потери контекста.
5. Сделать функциональные TGUI-тесты навигации, доступности старых функций и отсутствия самовольных команд.

## Отложенный архитектурный этап (не смешивать с текущим UI-циклом)

- Продолжить перевод остальных игровых устройств с legacy-взаимодействий и опроса на типизированные события,
  подписки и команды: атмосферные контроллеры/насосы, оставшиеся R&D операции, PDA-форматы, радио-потребители,
  дополнительные машины. Переходить по одному игровому сценарию с сохранением геймплея.
- Расширить IDE: подсказки по типизированным схемам, диагностика программ, отладка событий, виртуальная файловая система
  и инструменты для опытных игроков. Не превращать IDE в обязательный способ простых действий.
- Универсальный событийный инструментарий и автоматизация устройств остаются в `netDM-core`, а DM
  отвечает за местные права и применение физического эффекта.
- Отдельная, добровольная глубина игры: netrunning, цифровые агенты, самостоятельные серверы, программы,
  вторжения и защитные механизмы. Эти возможности не должны усложнять обычную работу станционных консолей.

## Критерии готовности

- Новый игрок открывает терминал, понимает назначение экрана и находит устройства без знания команд.
- Никакая карточка не исполняет опасное действие только при наведении/переключении вкладки.
- Из простого действия можно перейти к источнику, маршруту, схеме сервиса и затем к полноценному Shell.
- Разрыв сети, незавершённая операция и отсутствие прав явно видны; не имитируются локально.
- Работающие сценарии Shell, IDE и существующие игровые сетевые тесты не деградируют.

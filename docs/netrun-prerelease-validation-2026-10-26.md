## Продолжение: носимые узлы, старт РНД, пакеты и фотографии

Носимые узлы следят за всей цепочкой физических владельцев. ПДА, HUD, нейроинтерфейс,
импланты и вложенные предметы отмечают движение сразу, без ожидания опроса. Смена
владельца, nullspace и удаление контейнера обновляют подписки; обычный шаг по полу
не строит цепочку заново. Пять native carrier-тестов проходят.

## Итог архитектуры

Отдельный DNS исключён из рабочего протокола. Физическая сеть и общие деревья
маршрутов принадлежат `netrun_topology`; локальные устройства присоединяются
через APC. Для связи с другими секторами используются существующие физические
транзитные узлы. Единый индекс служб отвечает только за обнаружение; состояние
машин и исследовательские данные в него не копируются.

| Владелец | Ответственность |
|---|---|
| `core/topology.dm`, `core/routes.dm` | Физические узлы, APC, общие деревья инфраструктуры и поколения доступности |
| `core/service_registry.dm` | Жизненный цикл служб, индекс типа/тега, барьер запуска, уведомления готовности |
| `core/service_discovery.dm` | Асинхронное обнаружение, объединение запросов, ограничения и отмена |
| `core/machine_routes.dm` | Текущие кабели конечных узлов, кеш пар и сборка пути через APC |
| `core/machine_transport.dm` | Сообщения, пакеты данных, задержка, повторная проверка доставки и журнал |
| `core/delivery.dm`, `core/task_scheduler.dm` | Общие допуск, таймер, отмена, бюджет MC и продолжение работы |
| Адаптер машины | Штатные права, выбор получателя и реальное действие |

Прежние пути типов DNS-машины и платы оставлены для совместимости старых карт
как обычный информационный сервер. Они не публикуют DNS-службу, не открываются
отдельным исследованием и не создаются как отдельный сервер на старте.
Информационный сервер с семенем размещается на свободном месте телекоммуникаций.

## Обнаруженные проблемы и исправления

| Проблема | Причина и исправление |
|---|---|
| Просадки при движении с открытым нетраном | Движение ставит объединяемую задачу привязки. Стабильные APC-маршруты и неподвижные проекции сохраняются; обновляются изменившиеся конечные узлы и их связи. Pixi также раскладывает только изменившиеся маркеры. |
| Пакеты накапливались, цепочка PDA задерживалась | Готовая работа будит общий обработчик в текущем тике. Локальная задержка короче тика допускается к MC без дополнительного таймера на каждом звене. Сохраняются бюджет и проверка маршрута. |
| Дублирование сетевого состояния | Удалены копии каталогов DNS в машинах, запросы/ответы DNS, повторяющие таймеры и отдельное владение деревьями в транспорте. |
| Пачка запросов повторяла дорогой поиск | Получатели вычисляются один раз на пачку. Дальнейшая рассылка выполняется ограниченными порциями; исходные сообщения учитываются до завершения. |
| Переполненная очередь оставляла пустые задачи | Сначала допускается сообщение, затем задача. Отклонённый пустой запрос сразу освобождает слот, ожидание и подписку. |
| Запросы зависали после поздней загрузки карты/шаттла | Реальный прогон обнаружил 491 ожидающее обнаружение уже после успешной регистрации атмосферы. Повторное открытие барьера готовности теперь наблюдает общий обработчик, который ставит одно ограниченное пробуждение без обязательной смены APC. |
| Массовый перебор атмосферных тревог | Поиск контроллеров и устройств использует существующий индекс по отсеку. Совместимость частоты, текущее питание, путь и приём проверяются отдельно. |
| Атмосферные узлы не регистрировались после старта/смены канала | Штатные изменения частот публикуют состояние. После полной инициализации переиндексируются окончательные привязки. До подтверждённой доставки действуют ограниченные повторы; после подтверждения таймер останавливается. |
| Отключённая тревога или её замена | Локальные устройства теряют подтверждение соответствующего контроллера и вновь регистрируются. Отсутствие подходящего контроллера не создаёт постоянный поток пакетов. |
| Двойное начисление исследования при связанных серверах | Все способы обнаружения проходят одну политику выбора получателя. Из общей БД выбирается один физический сервер для мутации. |
| Потеря/воскрешение исследований через машины | Авторитетная БД принадлежит физическому серверу или явно связанной группе. Последний уничтоженный владелец удаляет БД; клиентские снимки её не восстанавливают. |
| Публикация исследований блокировала обработчик | Изменения публикуются порциями по четыре подписчика; одинаковая ревизия не вызывает повторную публикацию. Удаляются подписки прежнего владельца. |
| Кнопка археологического исследования не работала | Добавлена реальная серверная операция с проверкой артефакта и однократным потреблением. Тестируется цепочка исследований и штатные потребители БД. |
| Разрыв нейролинка оставлял сущность | Удаление импланта/узла возвращает владельца немедленно. Изменение транзитной доступности ставит одну критическую проверку следующего MC. Возврат терминален, удаляет сущность/действия и применяет одну штатную травму мозга: 20 урона с потолком 150. |
| Связь требовала NTnet-реле | Для пакетов связи разрешён штатный telecomms-маршрут с проверкой мощности, направлений, этажей и частот обоих концов. Исследования и атмосфера такой маршрут не получают. |
| Старый LAN оставался видим после перемещения | Инкрементальная перепривязка больше не добавляет прежний LAN в достижимые сети. Смена домашнего LAN обновляет права, даже при просмотре другого этажа. |
| Каталог этажей не обновлялся от невидимого узла | Изменение этажа/сектора/LAN известного невидимого узла обновляет каталог, сохраняя текущую выбранную область. |
| Камера с изменённым тегом пропадала из точного поиска | Общий setter обновляет штатный кеш камер и индекс служб. Мигрированы runtime-переименования роботов, bodycam, интегральных схем и создаваемых камер; проверяется коллизия с уже существующим тегом. |

Повторы регистрации: сначала каждые 5 секунд, после десяти попыток — каждые
30 секунд до успеха. Без подходящего работающего контроллера попытки останавливаются;
его появление или восстановление питания вновь запускает регистрацию.
Встроенные `readme.txt` формируются из роли
машины и контрактов сервисов; пользовательские файлы не перезаписываются.

## Ограничения работы

- MC по умолчанию: 6 мс, минимум при нагрузке 1 мс, максимум 192 задачи за проход.
- Кеш общих физических деревьев: 512 корней. Кеш пар устройств: 8192 путей.
- Обнаружение: 64 сочетания службы/тега на источник, 64 сообщения на запрос,
  4096 ожидающих исходных сообщений. Пакетов данных одновременно не более 2048.
- Допуск ожидавших обнаружений — по восемь. Рассылка — до восьми шагов за задачу,
  включая создание копии пакета и завершение исходного сообщения.
- Начальная топология строится после завершения инициализации подсистем в лобби.
  Публикация окончательных привязок служб — по 32 за задачу; полезные APC-деревья
  подготавливаются по одному.

Бюджет MC проверяется между задачами, поэтому отдельная дорогая операция может
его превысить. Нельзя интерпретировать 6 мс как гарантированный предел любой
сериализации, полного построения представления или штатного callback машины.

### Нагрузки

В серверном наборе проверяются 2000 неподвижных узлов, восемь носителей,
24 шага каждого и 192 UI-опроса; повторный проход 4096 пар устройств;
1024 заменяемых снимка плюс 32 самостоятельные команды; рассылка исследований
64 настоящим подписчикам; полноценная PDA-цепочка через штатные telecomms-машины.

Полный прогон 340 тестов: движение не вызвало полного перестроения
ни одного из восьми представлений и ни одной повторной проекции неподвижных
2000 узлов. CPU всех 24 перемещений восьми носителей — 57,27 мс, пик одного
шага — 10,98 мс; 192 UI-опроса — 572,43 мс суммарно, пик — 11,48 мс.
PDA-цепочка выполнилась за 0,1 секунды игрового времени. Два прохода 4096 пар
заняли 731,25 мс; второй проход использовал те же объекты путей.
В рассылке исследований 64/64 подписчика получили последнюю ревизию,
остаток очереди — 0.
Для 1024 снимков и 32 команд пик собственных пакетов составил 5; все команды
доставлены по одному разу, после остановки производителя очередь опустела.
Это измерения синтетического тестового мира, без сетевой задержки живых клиентов.

Первое полное построение этих восьми представлений всё ещё стоит около 1,74 с
CPU суммарно, в среднем около 217 мс на представление из 2009 узлов. Это отдельный
синхронный холодный путь, он не входит в измерение движения.
Большой первый снимок и массовые изменения прав требуют отдельного профилирования
на целевой станции; инкрементальная обработка движения не доказывает их дешевизну.

Заключительный клиентский CPU-микробенчмарк раскладки, база до исправления

6000 / 64 — 5,62 → 1,06 мс; 20000 / 128 — 21,97 → 5,00 мс.
Он измеряет только JavaScript-раскладку и не является измерением WebGL или

### Реальная «Мирная Синдикат Станция»

Отдельный тест загружает `_maps/peacesyndicatestation.json`, сохраняет реальные
частоты/питание/конструкторы устройств, не открывает UI для принудительного
опроса. Проверяется R&D и более ста совместимых пар «устройство — тревога»
на станции. Устройства в отсеках без контроллера или без питания не выдаются
за ошибки доставки.

Заключительный результат: **PASS, 1/1**. На станции 134 питаемых APC.
Оба реальных устройства R&D (vent layer2, scrubber layer4) зарегистрированы
на штатной частоте 1439: отсутствующих устройств 0, повторов 0, незавершённых
запросов у них 0. Службы DNS нет.

По станции проверено **1235 совместимых пар «устройство — тревога»**;
не зарегистрированных пар — **0**. Это число пар, а не уникальных устройств:
в одном отсеке может быть несколько тревог.

Заключительная проверка показывает **waiting=0, queued=0, packets=0**.
Во время стартового обмена очереди могут быть непустыми; тест проверяет их
полное опустошение после доставки. Два mapped-сервера РНД используют один techweb;
четыре настоящие консоли получили привязку и снимки без ручного вмешательства.
Клиентов РНД — 40, нуждающихся в снимках — 36, текущих подписчиков — 32.
Два устройства R&D также проверены на массивы `filter_types`. Фотография настоящей
камеры R&D экспортирована через браузерный base64-путь в один PNG 288×288 и осмотрена.

Предыдущие диагностические прогоны выявляли застрявшие обнаружения и излишнюю
подписку исследовательских клиентов. Проверки не ослаблялись: устранены причины,
после чего повторно проверены все совместимые атмосферные связки и РНД.

## Что пока не подтверждено

Автоматическая проверка безопасности отклонила доступ браузера к localhost.
Поэтому фактическая геометрия PDA/машин, WebGL, масштаб 75/100/125% и поведение
в настоящем клиенте BYOND не проверены. Готовые production-фикстуры и команды
ручной проверки находятся в `tgui/packages/tgui/interfaces/NetrunTerminal/PIXI.md`.
DOM-тесты не заменяют такую проверку.

Также не проведён сеанс с большим числом реальных подключённых игроков и
длительным раундом. Нагрузочные сценарии показывают объём серверной работы,
ограниченность очередей и правильное завершение операций, но не гарантируют
задержку в живом раунде.

Связанные исследовательские серверы используют один авторитетный techweb.
Сетевое разделение не создаёт независимых расходящихся реплик; выключенный
сервер сохраняет память, уничтожение последнего владельца её удаляет.
Физический диск остаётся явной резервной копией.

Эти ограничения не позволяют объявить проверку релиза полностью завершённой.

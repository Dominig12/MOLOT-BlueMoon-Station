# Нетраннинг — сетевой слой станции

Модуль добавляет поверх NTnet полноценную сеть: адресуемые узлы в машинах,
локальные сети отделов, сессии доступа, взлом, трассировку, хранилища данных,
сетевых сущностей и общий TGUI-терминал для всего этого.

## Топология

```
                  NTnet (глобальная сеть, живёт пока работает хоть один квантовый ретранслятор)
                    │
   ┌───────────┬────┴──────┬────────────┬──────────┬──────────┐
 [шлюз ОБЩ] [шлюз ИНЖ] [шлюз МЕД]  [шлюз НИО] [шлюз СБ]  [шлюз КОМ]   ← шлюз = вход в ЛВС, у него своя защита
   │           │           │           │          │          │
 узлы        узлы        узлы        узлы       узлы       узлы       ← шлюзы, APC, камеры, турели, торгоматы, серверы...
```

* **ЛВС** (`/datum/netrun_network`) назначается узлу автоматически по зоне, в которой стоит машина
  (`netrun_lan_for_area`). Сеть СБ и командования защищены сильнее, общая сеть — слабее всего.
* Объекты вне станции и шахты попадают в изолированную «внешнюю» ЛВС своего Z-уровня: к ней нет
  маршрута через NTnet, туда можно попасть только физически (деком или локальным терминалом).
* **Узел** (`/datum/component/netrun_node`) — компонент на атоме. Знает свой адрес, тип, уровень
  защиты, список команд и признаки «онлайн/офлайн».

## Точки доступа (origin)

Все интерфейсы — один датум `/datum/netrun_console` с общим TGUI `NetrunTerminal`. Отличается только
то, откуда идёт подключение:

| Точка        | Канал       | Что открыто сразу                    | Наказание за трассировку            |
|--------------|-------------|--------------------------------------|-------------------------------------|
| Терминал     | проводной   | своя ЛВС + NTnet                     | терминал блокируется                |
| Кибердека    | провод в машину | ЛВС машины, к которой подключились | дека перегорает на время            |
| Имплант      | беспроводной| NTnet                                | урон мозгу, оглушение               |
| NTOS-программа | беспроводной | NTnet                              | сеть выбивает сессию                |
| Сущность     | изнутри узла| ЛВС узла-носителя + NTnet            | урон целостности, выброс из узла    |
| Интегралка   | беспроводной| NTnet + ЛВС, где стоит сборка        | — (только легальный доступ по ключу)|

## Доступ

Уровни: `НЕТ < ГОСТЬ < ПОЛЬЗОВАТЕЛЬ < ROOT`.

* **Легальный** — по ID-карте пользователя (`allowed()` машины даёт ПОЛЬЗОВАТЕЛЯ, `ACCESS_NETWORK`
  или капитанский доступ поверх этого — ROOT) или по сетевому ключу ЛВС (для интегралок).
  Легальные действия только пишутся в журнал.
* **Нелегальный** — через взлом. Каждое действие выше легального уровня поднимает **трассировку**.
  Взлом шлюза ЛВС открывает гостевой доступ ко всем её узлам.

## Взлом (Breach Protocol)

Матрица шестнадцатеричных кодов, буфер ограниченной длины и 1–3 «демона» — последовательности,
которые надо собрать в буфере. Первый выбор — из верхней строки, дальше столбец/строка чередуются.
Демон 1 даёт ПОЛЬЗОВАТЕЛЯ, демон 2 — ROOT, демон 3 — сбрасывает трассировку. Размер матрицы,
длина демонов, время и скорость трассировки зависят от защиты узла; размер буфера — от железа
и установленных программ. Матрица всегда решаема: демоны нарезаются из заранее построенного пути.

## Трассировка

Растёт от нелегальных команд и во время взлома, медленно спадает в простое. На 100%:
сессии рвутся, доступ отзывается, точка подключения получает ответный удар (см. таблицу), в журнал
сети и NTnet пишется местоположение нарушителя, срабатывает IDS NTnet. После этого — блокировка
на минуту.

## Данные

`/datum/netrun_file` — тексты, ключи ЛВС, программы-демоны, «семена» сущностей. Хранилища есть у
серверов, терминалов, дек, имплантов, шардов данных и самих сущностей. Программы-демоны влияют на
взлом: `buffer.exe` (+буфер), `icepick.exe` (−защита), `cloak.exe` (−трассировка).

## Сетевые сущности

`/mob/camera/netrun_entity` живёт внутри узла-носителя: видит и слышит вокруг него, говорит его
динамиком, прыгает по узлам своей ЛВС (стрелками — к ближайшему узлу в этом направлении) и через
NTnet. У неё есть целостность; ROOT-команда «очистка» на серверах и терминалах бьёт по сущностям внутри.

Как стать сущностью:
1. **Погружение** — нетраннер с имплантом «Нейролинк» оставляет тело без сознания и уходит в сеть.
   Урон телу выбрасывает обратно, смерть сущности — травма мозга.
2. **Гост-роль** — «семя ИИ» в сервере данных создаёт точку спавна для призраков.
3. **Оцифровка экипажа** и **антагонист** — следующие этапы (см. план).

## План этапов

1. **Ядро + MVP (этот этап)** — сеть, ЛВС, узлы, сессии, команды, взлом, трассировка, файлы,
   терминал, сервер, дека, шард, имплант, погружение, гост-роль, цели: шлюзы, APC, камеры, турели,
   торгоматы; интегралки, NTOS-программа, журнал и IDS NTnet, исследования.
2. **Люди и силиконы** — кибер-импланты как узлы (квикхаки), борги и ИИ, вид через камеры.
3. **Инфраструктура** — телекомы (перехват/подмена радио), серверы РнД (кража/порча исследований),
   торговля данными, оцифровка экипажа (нейросканер), антагонист-сущность.
4. **Сайты** — мост между SSntnet и игровой сетью: сайты, публикующие API, запросы к узлам с сайтов.

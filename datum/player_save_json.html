player_save_json
/datum/player_save_json

Два поколения: оборванная запись одного файла не повреждает другое поколение.

Vars

legacy_copy_prefixИмя и хеш последней открытой копии старого .sav.
loaded_treeПоследний проверенный или успешно записанный снимок; наружу выдаются документы.
node_jsonJSON неизменяемых узлов используется повторно при сравнении и публикации снимка.

Procs

check_revisionСовместимый писатель тоже не должен затирать изменения другого датума после открытия.
commit_treeЕдинственная точка публикации: снимок становится текущим только после записи.
empty_snapshotПустой снимок поверх файлов, которые корень не публикует: их содержимое не читается.
encode_nodesПорядок ключей и представление пустого дерева совпадают с json_encode(tree).
legacy_viewКорень и один раздел старого .sav без разбора остальных анкет: вход игрока до переноса. Только для чтения - полный снимок по такому savefile потерял бы остальные слоты, commit его отвергает.
on_first_publishПервая запись JSON на диск, в том числе после переноса старого сейва.
open_legacy_copyКопия старого .sav: даже чтение отсутствующего ключа изменяет savefile BYOND. Вызывающий обнуляет savefile и только потом зовёт close_legacy_copy(): BYOND дописывает файл при удалении.
peek_generationЗаголовок служит только подсказкой порядка; выбранный файл всё равно проверяется целиком.
read_fieldДля меню достаточно проверить файл и одно поле, не декодируя всю анкету.
read_fieldsНесколько полей одним чтением файла; null - ошибка в error.
verify_legacy_copyЗвать после чтения и до любой записи в копию: BYOND замечает повреждение по ходу чтения.
